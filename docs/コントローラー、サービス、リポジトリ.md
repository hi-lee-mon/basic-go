## CRUD実装
Router/Controller/Service/Repository/resourceの構成とする
各層は必ずIFに依存することで依存性の逆転を行う

### repository
serviceから受け取った値を使ってリソース情報を取得してserviceにわたす

serviceとrepositoryで受け渡す値にはmodelsを使用する。

#### 実装の流れ
1.Interfaceを定義する

Interfaceはrepositoryの利用者であるservice向けの契約。
serviceはrepositoryがどのメソッドを持っており、何を返すかだけを知る。

2.リポジトリ構造体を定義する
リポジトリのクラスと理解すればOK。後続のNew*でインスタンスとする

3.New関数を定義する
New関数はリポジトリ構造体の実装を返す（インスタンス）

4.IFをもとにメソッドを定義する
このメソッドはserviceから呼ばれる。

なのでメソッドの引数や戻り値はserviceにわたるということを理解しておけばOK

### service
リポジトリを呼び出し、その結果をコントローラーに渡す

DTOをmodelに変換する。modelはrepositoryに渡す。

#### 実装の流れ
1.Interfaceを定義する

Interfaceはserviceの利用者であるcontroller向けの契約。
controllerはserviceがどのメソッドを持っており、何を返すかだけを知る。

2.サービス構造体を定義する
サービスのクラスと理解すればOK。後続のNew*でインスタンスとする

3.New関数を定義する
New関数はサービス構造体の実装を返す（インスタンス）

4.IFをもとにメソッドを定義する
このメソッドがコントローラーから呼ばれる。

なのでメソッドの引数や戻り値はコントローラーにわたるということを理解しておけばOK

serviceのメソッドの中でrepoを呼び出す。
repoの戻り値を使って処理して、結果はコントローラーに返す

### controller
サービスを呼び出し、gin.Contextを通じてHTTPレスポンスを直接クライアントに返す

mainから受け取ったクエリパラメータやパスパラなどのリクエスト情報を使って
バリデーションを行ったのち、serviceのメソッドを実行。
serviceの戻り値のエラーハンドリングを行う

#### 実装の流れ
1.Interfaceを定義する

Interfaceはcontrollerの利用者であるmain向けの契約。
mainはcontrollerがどのメソッドを持っており、何を返すかだけを知る。
（mainはルーティング登録のみ行い、コントローラーメソッドをハンドラーとして渡す）

2.コントローラー構造体を定義する
コントローラーのクラスと理解すればOK。後続のNew*でインスタンスとする

3.New関数を定義する
New関数はコントローラー構造体の実装を返す（インスタンス）

4.IFをもとにメソッドを定義する
このメソッドがmainから呼ばれる。

なのでメソッドの引数や戻り値はmainにわたるということを理解しておけばOK

コントローラーのメソッドの中でserviceを呼び出す。
serviceの戻り値を使って処理して、結果をクライアントに返す
