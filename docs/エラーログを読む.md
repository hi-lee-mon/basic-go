次のエラーがスタックトレースでnil へのアクセスが原因でエラーになっていることがわかる。

すぐ下にpanicとある。さらにその下を見るとこれはよくわからないが、エラー時の経路だと思う
そのしたにauth_service.goと自分の実装がでてきたのでここでエラーになったと考える。

行数は58行目で
```go
	foundUser, err := s.repository.FindUserByEmail(email)
	if err != nil {
		return nil, err
	}
  // ここでエラーが出ている
	err = bcrypt.CompareHashAndPassword([]byte(foundUser.Password), []byte(password))
```

`err = bcrypt.CompareHashAndPassword([]byte(foundUser.Password), []byte(password))`がエラーの発生源だとはっきり書いてある。
foundUserやpasswordなどが前の処理からわたってきているため、これがエラーの原因だと推測できる。
つまりそれらがどこから来たのかを考える必要がある。

さらにエラーログを遡るとコントローラーになるが、コントローラーはpasswordのみ関係しており、passwordのハンドリングはコントローラーでしているので関係なさそう。

したがって直前の処理である`foundUser, err := s.repository.FindUserByEmail(email)`が怪しい。

`s.repository.FindUserByEmail`を見ると色々処理が書いてある。このときどの処理に入るのかを思考する必要がある。
リポジトリなのでここでSQLエラーの結果分析が役に立つ。SQLの結果は0件だったのだから、ここでは0件の分岐に入るはずで、そこに問題があると考えられる。

```go
if result.Error.Error() == "record not found" {
    return nil, nil  // ← ユーザーが見つからないときに (nil, nil) を返している
}
```
これが原因。errがnilなのでハンドリングできておらず、foundUserがnilなのにPasswordでアクセスしてパニックした。
